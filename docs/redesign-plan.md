# Redesign plan (proposed Phase 7R)

Status: **approved by the owner on 10 November 2026.** R1 to R4 are done and were restyled on 10 November 2026 when the owner replaced the first visual direction (see [DESIGN.md](DESIGN.md) and the last row of the redesign table in [decisions.md](decisions.md)); the colour, type, logo and motion rows below describe the first direction where they differ. R5 is done; R6 (app shell, dashboard and the Insights page) is done. R7 (the deal space) is built, with Bryntum charts for the timeline and a Deadlines page; R8 (the dispute workspace, with its comparison, packet, answer and appeal panels) is built. R9 (landing page) is next. Branch: `redesign`, from `dev`.

## Goal

Give PactPal a public face and a signed-in experience that read as a finished, independent product: a scroll-driven landing page, a dedicated sign-in page, a seller dashboard, a deal space, and calm buyer pages. Behaviour stays the same; the look, layout and navigation change.

## The one server addition

`GET /api/deals/overview`, for the signed-in person, returns each of their deals with what the dashboard and the deals table show:

- everything `GET /api/deals` returns today
- total agreed amount (minor units and currency)
- stage: drafting, awaiting buyer, in progress, delivered, disputed or complete (derived from the deal status, timeline progress and open disputes by one pure function in a package, with tests)
- next step: its label, who it waits for, its due date and whether it is overdue (from `packages/timeline`)
- completeness score (from `packages/score`)
- unread chat messages and unread notifications
- open dispute, if any, with its respond-by date
- time of the latest activity

Rules: read-only, no ledger events, the same access checks as the deal list, and the same tests as other routes. As built (see decisions.md) it reuses each deal's existing readers for the 200 most recently changed deals, instead of a fixed number of set-based queries. `GET /api/deals` stays as it is.

## What does not change

Server behaviour apart from the one new read-only address, ledger events, guardrail wording (the footer's "Sandbox only" becomes the agreed test-mode line), buyer link flow, sign-in flow, tab addresses, the live chat connection.

## Risks

| Risk                                                                         | Handling                                                                                                                                                                         |
| ---------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| jscpd fails once 45 panels are restyled                                      | Styles come only from primitives and tokens; panels are migrated a surface at a time                                                                                             |
| AG Grid, AG Studio or StringTune fail `pnpm audit --prod` or blow the bundle | Checked at install; fall back to AG Grid Community, a token-styled table or native CSS scroll timelines and log it                                                               |
| AG Studio and AG Grid Enterprise are commercial; the trial lasts 45 days     | Fine for now; before real sellers use PactPal, buy a licence or drop back to AG Grid Community (MIT) and plain charts. Both sit behind one lazy screen, so the swap is contained |
| AG Studio cannot be themed close enough to PactPal's look                    | Found in the R6 trial; if so it moves to its own Insights page rather than the dashboard home                                                                                    |
| Pinned scroll breaks the keyboard, find-in-page or anchors                   | Sections stay real DOM in reading order; pinning is visual only; phones get simple reveals                                                                                       |
| The size of the work                                                         | Steps are independent and each leaves the app working and verified                                                                                                               |
